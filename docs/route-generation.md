# Automatic Route Generation

## Overview

Routes are automatically generated from the `views` directory structure, controlled by `app-config.ts`. This system provides:

- **Automatic discovery** - New views are automatically added to routes
- **Manual control** - Rearrange routes in `app-config.ts`
- **Exclusions** - Ignore certain views from navigation (e.g., NotFound, 404)
- **Type safety** - Full TypeScript support

## How It Works

### 1. View Registry

Views are registered in `src/app/routes.tsx`:

```typescript
const viewRegistry: ViewRegistry = {
  Catalog,              // Maps to /catalog
  ContainerDetail,      // Maps to /container-detail
  Support,              // Maps to /support
  'Settings/General': GeneralSettings,  // Maps to /settings/general
  NotFound,             // Excluded from nav, but available for 404
};
```

### 2. Configuration File

`src/app/app-config.ts` controls route generation:

```typescript
export const appConfig: AppConfig = {
  routes: {
    autoGenerate: true,        // Enable auto-generation
    viewsDirectory: 'src/views', // Directory to scan
    ignore: [                  // Views to exclude from nav
      'NotFound',
      '404',
      // ...
    ],
    manualRoutes: [            // Manual route definitions (take precedence)
      {
        path: '/',
        title: 'Dashboard',
        label: 'Dashboard',
        view: 'Catalog',        // Maps to Catalog component
      },
      // ...
    ],
  },
};
```

### 3. Route Generation

Routes are generated by:
1. Taking manual routes from config (these take precedence)
2. Auto-generating routes for views not in manual config
3. Excluding views in the `ignore` list
4. Merging everything together

## Adding a New View

### Step 1: Create the View

```typescript
// src/views/LandingPage/LandingPage.tsx
export const LandingPage: React.FC = () => {
  return <div>Landing Page</div>;
};
```

### Step 2: Register the View

Add to `src/app/routes.tsx`:

```typescript
import { LandingPage } from '@views/LandingPage/LandingPage';

const viewRegistry: ViewRegistry = {
  // ... existing views
  LandingPage,  // Auto-generates route: /landing-page
};
```

### Step 3: (Optional) Add to Manual Routes

If you want to customize the route (path, title, label, or position):

```typescript
// src/app/app-config.ts
manualRoutes: [
  {
    path: '/',
    title: 'Home',
    label: 'Home',
    view: 'LandingPage',  // Uses LandingPage component
  },
  // ... other routes
]
```

## Route Configuration Options

### Manual Route Properties

```typescript
{
  path: '/custom-path',      // Custom URL path
  title: 'Page Title',       // Page title (for document title)
  label: 'Nav Label',        // Navigation label
  view: 'ViewName',          // View component name (from registry)
  group: 'Group Name',        // Optional: Group routes together
  routes: [                   // Optional: Nested routes
    {
      path: '/custom-path/sub',
      title: 'Sub Page',
      label: 'Sub',
      view: 'SubView',
    },
  ],
}
```

### Auto-Generated Routes

If a view is in the registry but not in `manualRoutes`, it's auto-generated:

- **Path**: Converted from view name (Catalog → /catalog)
- **Title**: Converted from view name (ContainerDetail → Container Detail)
- **Label**: Same as title

## Excluding Views from Navigation

Add view names to the `ignore` array in `app-config.ts`:

```typescript
ignore: [
  'NotFound',  // Excluded from nav, but still available for 404 route
  '404',
  '500',
  // ...
]
```

## Route Ordering

Routes appear in the order they're defined in `manualRoutes`. Auto-generated routes are appended after manual routes.

To change order, rearrange entries in `manualRoutes`.

## Dynamic Routes

Dynamic routes (with parameters) must be defined manually:

```typescript
{
  path: '/containers/:name',  // Dynamic parameter
  title: 'Container Detail',
  label: 'Container Detail',
  view: 'ContainerDetail',
}
```

The component mapping automatically handles dynamic route matching.

## Examples

### Example 1: Simple Auto-Generated Route

```typescript
// View registry
const viewRegistry = {
  About,
};

// Auto-generates:
// {
//   path: '/about',
//   title: 'About',
//   label: 'About',
// }
```

### Example 2: Manual Route Override

```typescript
// app-config.ts
manualRoutes: [
  {
    path: '/about-us',        // Custom path
    title: 'About Us',        // Custom title
    label: 'About',           // Custom label
    view: 'About',            // Uses About component
  },
]
```

### Example 3: Grouped Routes

```typescript
manualRoutes: [
  {
    path: '/settings',
    title: 'Settings',
    label: 'Settings',
    group: 'Settings',        // Groups routes in nav
    routes: [
      {
        path: '/settings/general',
        title: 'General Settings',
        label: 'General',
        view: 'Settings/General',
      },
    ],
  },
]
```

## Benefits

1. **Less Maintenance** - Add view, register it, done
2. **Type Safety** - Full TypeScript support
3. **Flexibility** - Manual control when needed
4. **Consistency** - Automatic path/title generation
5. **Single Source of Truth** - `app-config.ts` controls everything

## Troubleshooting

### Route Not Appearing

1. Check view is in `viewRegistry`
2. Check view is not in `ignore` list
3. Check manual route has correct `view` name
4. Verify component is exported correctly

### Route Path Wrong

Override in `manualRoutes` with custom `path`.

### Route Order Wrong

Rearrange entries in `manualRoutes` array.
